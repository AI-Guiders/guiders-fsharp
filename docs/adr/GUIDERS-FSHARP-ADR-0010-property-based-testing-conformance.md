## Context

Тестовая культура репы до сих пор — юнит-тесты с фиксированными примерами. Опыт миграции `Ide.Session` на property-based testing (FsCheck 3.6.0) показал две вещи:

1. **Юнит-тесты не ловят то, чего не умеют воображать.** Восемь юнит-тестов `CompileGraph` (ordered-цепочка, diamond, фиксированные ключи) были зелёными, а первый же прогон FsCheck сгенерировал строки с unpaired-суррогатами и вскрыл коллизию `unitKey`: `Encoding.UTF8` схлопывает их в U+FFFD, две разные заморозки давали один ключ артефакта — кэш `H` молча переиспользовал бы чужой IL. Это не экзотика: PBT нашёл баг первой сотней случайных входов, который ручной пример не находит в принципе.
2. **Математика репы уже записана как `∀`.** Аксиомы в `docs/math/` (IB1, SN1–SN6, законы снапшотов, отношения) — это дословно свойства: «для любого графа, для любой дельты…». Юнит-тест проверяет фантазию о графе; свойство проверяет саму алгебру.

## Decision

1. **Конформанс = свойства.** Для чистых функций, алгебр и парсеров тесты формулируются как свойства `∀…` (FsCheck 3.6.0, `FsCheck.Xunit`). Имена свойств несут аксиомные идентификаторы (`IB1 …`, `SN2/SN4 …`) — исполняемая математика, а не описание кейсов.
2. **Юнит-тесты удаляются, когда свойство покрывает их.** Правило покрытия: пример живёт, только если он фиксирует контрпример/регрессию, которую свойство не выражает (golden-файлы, зафиксированные баги). Иначе — удалён.
3. **Что не мигрирует:** golden-файлы, IO/интеграции, фиксированные сценарии интерфейсов, тривиальные shape-тесты записей — там свойств либо нет, либо они ничего не ловят.
4. **Дисциплина генераторов:** ацикличность по построению (рёбра только из ранних в поздние), доменные guard'ы фиксируются в комментарии свойства (null вне домена — нормализация, а не guard в коде), генератор не содержит ручных падов с потенциальным вечным циклом.
5. **Инфраструктура:** FsCheck 3.6.0 в CPM (`Directory.Packages.props`); F#-поверхность — `FsCheck.FSharp` (`Prop.forAll (Arb.fromGen gen)`, квалифицированный `Gen.*`, CE `gen`). Для будущих C#-проектов федерации — `FsCheck.Fluent`, отдельная механика.
6. **Метаморфные оракулы — любимый приём:** два представления одной сущности обязаны согласовываться (например, ordered-топология ≡ выписанная явная цепочка рёбер).

## Consequences

- Каждый релизный прогон гоняет тысячи случайных конфигураций вместо десятка придуманных.
- Стоимость владения: генераторы — код, который нужно читать; дисциплина п.4 обязательна.
- Свойства документируют алгебру лучше тестов: имя свойства = аксиома, контрпример = минимальный.
- Parity-тесты против C#-сиблингов остаются примерными (они про совпадение реализаций, не про законы) — до закрытия их релизных цепочек.
